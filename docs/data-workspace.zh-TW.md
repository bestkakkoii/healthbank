版本：RC10；契約核對日期：2026-10-28（臺灣時間）。以下是 **Healthbank 自有 API**，不是健保署正式開放 API。上游路徑與證據分別見[登入／檢驗協定](nhi_protocol.md)、[資料來源契約](provider-data.md)、[原始文件契約](provider-documents.md)。

## 1. 工作流程

1. 使用者完成官方登入及人工圖形驗證碼。Go 以個別記憶體 Cookie jar／JWT 維持官方工作階段；瀏覽器只持有本站 HttpOnly 使用階段 Cookie。
2. 「醫療資料」工作區讀取來源目錄。使用者可選來源，預設取得支援的最大範圍；檢驗資料可一併取得。
3. 先逐一取得所有選取來源的清單，再逐筆取得清單內明細，並繼續處理明細內的下一層識別。請求按順序執行，不同來源的一筆錯誤不抹除其他成功結果。
4. 搜尋、日期、院所及來源篩選只影響顯示。草稿日期不會自動查詢、清空已取得內容或重設分析條件。
5. 原始附件由使用者明確下載；需要上游準備的檔案由獨立產製操作提出。一般資料拉取不會自動建立產製工作。
6. 匯出全部已取得資料，或還原先前資料包。資料包與主動下載的原始檔由使用者自行保存。

「取得最大範圍」不等於已證明終身資料完整。來源沒有獨立總數，或相同期間總數與實際陣列長度不一致時，`complete` 保持 `false`；成人健檢、特定篩檢、近期摘要及官方產製歷史各有自己的可回傳範圍。

## 2. 登入與查詢 API

所有 API 回應均為 `Cache-Control: no-store, private`。JSON 使用 UTF-8；錯誤不回傳帳密、官方 Cookie、JWT 或醫療原文。非 GET／HEAD 操作需同源與 `X-CSRF-Token`。已取得本站工作階段的瀏覽器也將此標頭附於有狀態的 GET／HEAD，綁定本頁所屬連線，避免另一分頁更換共用 Cookie 後讀入不同資料。`/api/session` 不帶此綁定，專門用於初始建立與重新確認。原生附件連結無法攜帶自訂標頭，另由當次不透明文件識別綁定；有效連線不存在時直接回傳 401，不新設 Cookie。

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/session` | 建立／讀取本站使用階段、取得 CSRF 與設定 |
| GET | `/api/auth/captcha` | 取得官方圖片與本站挑戰識別；不自動辨識 |
| POST | `/api/auth/login` | 提交 `identity_number`、`card_number`、`password`、`captcha`、`challenge_id` |
| POST | `/api/auth/logout` | 結束工作階段，清除記憶體報告及官方識別 |
| GET | `/api/data/catalog` | 公開來源能力目錄；不查詢個人資料、不證明該帳號具有每個來源 |
| GET | `/api/reports/current` | 讀取當次記憶體檢驗；不重新向官方查詢 |
| POST | `/api/reports/import` | 單一具檔名的 multipart `file`；驗證成功後切換至獨立匯入模式 |
| POST | `/api/reports/demo` | 建立明示合成資料的示範模式 |
| GET | `/api/reports?from=&to=` | 取得檢驗資料；空日期代表最大查詢範圍 |
| GET | `/api/supplementary?category=medicine&from=&to=` | 取得指定來源清單 |
| GET | `/api/supplementary?category=medicine&detail=<opaque-id>` | 取得該清單回傳的明細 |
| GET | `/api/documents?category=imaging&id=<opaque-id>` | 下載該資料來源回傳的原始附件 |
| POST | `/api/documents/prepare` | 明確提出官方檔案產製；JSON 為 `{ "category": "…", "id": "…" }` |

`detail`／文件／產製識別由伺服器建立，綁定目前官方使用階段、類別及來源父項目。瀏覽器不能指定上游 URL、官方 row ID 或其他人的識別。登出、登入逾時、成功重查對應清單後，舊識別失效。失敗重查保留原先仍有效的成功資料。

產製成功回應 HTTP `202` 與 `{ "status": "requested", "message": "…" }`，只表示已提出要求，不表示檔案已完成。使用者稍後重新取得原始檔來源／明細，再依官方實際狀態下載。產製不自動重試；不明網路結果不應重複建立工作。

檢驗回應包含 `session_token`，必須為目前或該成功切換操作建立的 64 位十六進位 CSRF 識別。前端在安裝檢驗、醫療資料包與後續設定／目錄前核對同一識別；同為 `import` 模式仍須精確相等。此值只供即時 API 核對，不寫入可攜醫療檔案或日誌。官方失效、`csrf_mismatch`、`session_changed`、`session_rotate` 或缺失的回應識別會清除舊醫療狀態；一般設定修訂衝突不因此清除資料。

已送出的登入／登出／匯入若遇到回應遺失，無法單憑前端例外判斷伺服器是否已執行。前端只重新讀取 `/api/session`：識別未變則保留原資料，已變則清除舊資料並採用已確認連線，無法確認則清除本頁醫療資料；不自動重播操作或宣稱刪除成功。

常見 HTTP：`400` 輸入／識別不符、`401` 登入失效、`403 csrf_mismatch` 頁面連線過期、`409 session_changed` 連線已更換、`424` 上游依賴失敗、`429` 新階段／排隊限額、`503` 請求／容量暫不可用、`500` 本站錯誤。容量拒絕附 `Retry-After`；不得把伺服器拒絕誤當成零筆來源。二進位下載開始後若來源中斷，會中止傳輸，不在檔尾追加 JSON 或把截斷內容宣稱成功。

## 3. 來源目錄與範圍

`GET /api/data/catalog` 回應：

```json
{
  "categories": [
    {
      "id": "medicine",
      "label": "用藥紀錄",
      "group": "用藥與就醫",
      "range_mode": "date_search",
      "has_details": true
    }
  ]
}
```

| `range_mode` | 實際行為 |
| --- | --- |
| `date_search` | 空 `from`／`to` 解析為 `1912-01-01` 至臺灣當日；指定期間須同時提供有效起訖。部分來源先發現項目，再於各項明細查詢完整期間。 |
| `source` | 使用官方已觀察的清單契約，讀取全部回應；不杜撰上游不存在的日期參數。範圍限制放在 `coverage`。 |

民國 1 年只是查詢下限，不是官方保有紀錄的最早年度。畫面年度篩選、檢驗查詢草稿與資料工作區的拉取條件分開。

## 4. 原始紀錄模型

清單與明細共用 `SupplementReport`：`category`、`entries`、`coverage`、`fetched_at`、可用時的 `start_date`／`end_date`、`complete`。

RC10 另提供 `contract_revision` 與有界 `diagnostics`。已知區塊缺失、選用區塊未提供、`null`、
空集合與已知結果欄位缺失分別記錄，不能都解讀為已確認沒有紀錄。診斷僅含固定代碼、訊息、
來源區塊識別與有界筆數，不帶來源個資。

來源欄位可含 `code`、`role`、`unit_basis`；日期可含 `date_role`／`end_date_role`，紀錄可含
`origin`／`contract_id`。這些語意只由已確認的來源欄位契約建立，未知就保留未知。
`unit_basis=public_contract` 表示單位來自公開欄位規格，不能偽稱本筆回應另有明示單位。
顯示期間相交只適用明確配對的入院／出院、申報起訖、有效期或來源期間；
不由給藥日數或同日紀錄推定日期區間。

檢驗另保留 `raw_check_date`／`raw_visit_date` 原文與 `exam_date`／`visit_date` 正規化值。篩選使用可解析日期；明細、CSV 與可攜 JSON/XML 保留原始日期文字，無效或空白來源日期不被補成另一日期。

每筆包含原始日期、院所、標題、來源及具名欄位；可帶來源種類、不同迄日、已知藥品代碼／數量／給藥日數、下一層明細、附件與產製動作。欄位值維持字串，避免把精確小數、不等式、定性文字與未知日數改造成假精確值。

API 僅投影已確認語意的醫療欄位；不轉出上游身分、權杖、內部 URL 或任意未知 JSON。需要來源完整原始文件時使用官方原始檔下載。原始文件的所有未知欄位不會被聲稱已建模或完成臨床判讀。

時間軸同時顯示檢驗及其他醫療來源。清單、明細及同日重複結果保留為不同紀錄；只有實際回傳的父子識別建立關聯，不以同日同院推定同次採檢或就醫。處方、建議續領期間、來源確認的調劑事件與實際服用分開。不同來源藥品代碼無法證明同一命名規則時，不直接合併成同藥品序列。

## 5. 部分成功、取消與容量

工作區分別記錄 `unqueried`、`loading`、`ready`、`failed`、`cancelled`；成功回傳空陣列與尚未查詢不同。每個來源另有已取得／待取得／失敗明細數量及獨立的原查詢範圍。

可分類的暫時讀取錯誤最多重試一次。續取跳過成功請求；偵測到登入失效時清除目前工作區醫療資料並要求重新登入。取消保留已完成回應，取消後晚到的回應不重新填入工作區。使用者已下載檔案及明確選擇保存的裝置端記憶，依各自清除方式管理。

來源單次 JSON 通常限制 16 MiB／50,000 筆；工作區與可攜格式另有總容量限制。到達上限會拒絕本次新增回應並保留此前成功內容，不截斷來源陣列後回報完整。依來源分次取得與匯出可降低單頁使用量。

### 按年／按月分批

登入後可在來源管理展開「按年／按月分批取得與保存」，明確指定完整起訖日期與每批期間。
最多 600 批，各批包含邊界日期且相鄰不重疊；第一批／最後一批截至使用者指定日期，包含閏日。
只有已選且 `range_mode=date_search` 的來源納入，另可選擇檢驗；沒有日期搜尋的來源明列排除，
仍由原本「取得全部可提供資料」操作讀取其實際範圍。來源索引本身若另有窗口，保留其全部回應及限制，
不偽稱被日期參數完整篩選，也不在客戶端刪除回傳原始紀錄。

每批先取得所選檢驗及清單，再處理全部回傳明細與下一層明細。停止保留成功結果，
接續不重取已完成項目。只有本批待取得項目已處理、手動匯出成功，且使用者勾選確認檔案已保存，
才能明確開始下一批；啟動下載本身不等於已證明磁碟保存。來源缺乏獨立總數時，這仍不是完整歷史證明。

開始第一批或下一批會取代工作區中所選來源的舊清單、明細、失敗狀態及保留附件；未選來源保留。
所選檢驗先清空，只有本批期間相符的成功檢驗回應進入本批資料包，不沿用上批結果。
本批資料包包含本批的成功內容與未完成狀態，附件不自動下載或嵌入。
若上游或容量限制使一批無法完成，可先保存部分內容、結束計畫，再改用較小期間。

工作區醫療紀錄仍合計限制 250,000 筆，每輪最多處理 50,000 筆明細識別；可分類的暫時錯誤另最多重試一次，未選來源也計入總容量。
只保留當前批次原文及先前批次的期間／筆數摘要，不在頁面累積所有原文、不自動去重，
也不把續取檢查點寫入瀏覽器儲存。重新載入或更換工作階段後需重新建立計畫；先前資料以使用者下載檔為準。
計畫結束後一般來源／檢驗操作恢復可用，目前這批已取得內容仍留在工作區。

## 6. 完整資料包

輸出格式識別：`healthbank.dataset.v2`；UTF-8 JSON，可選 BOM。仍接受嚴格 v1 匯入，但不替它補造產生版本或來源語意。檔案最大 128 MiB；嵌入附件總計最大 32 MiB，檢驗部分轉換成可攜 JSON 後最大 32 MiB。匯出與還原使用相同上限，超過時整份拒絕，不產生截斷或無法還原的檔案。另存 HTML／ZIP 匯入仍有 12 MiB 檔案與 6 MiB 展開 HTML 限制。

| 頂層欄位 | 內容 |
| --- | --- |
| `schema` | 固定格式識別 |
| `exported_at` | 匯出時間 |
| `producer` | Healthbank 版本、來源契約修訂、臨床目錄識別與目錄／證據雜湊；不是電子簽章或身分證明 |
| `imported_from` | 重新輸出匯入資料時，保留上一份資料包的產生版本；單層描述，不遞迴儲存整個歷程 |
| `laboratory` | `healthbank.lab.v1` 原始檢驗欄位及來源查詢／完整性資訊；不保存推算值或顏色判定 |
| `catalog` | 當時來源名稱、分組、範圍能力 |
| `data` | 全部已取得清單、明細、個別取得狀態、錯誤與查詢範圍 |
| `attachments` | 使用者明確加入的附件原始位元組、名稱、MIME、大小與 SHA-256 |

畫面只看某一年或搜尋某藥，不會縮小這份資料包。未取得明細及未加入附件保留缺漏狀態；僅有附件描述不等於已備份其內容。先前下載、後來來源重查而更換識別的檔案仍可保留於附件清單。

單一來源清單／明細匯出與完整資料包共用相同安全投影。官方工作階段識別在匯出時轉成只供檔案內關聯的 `archive_N`；產製動作、登入資料、Cookie、JWT 及同步設定身分不會匯出。還原前拒絕重複 JSON 欄位、孤立的 UTF-16 跳脫代理碼、未知危險結構、失聯明細、不合理容量、無效 UTF-8、可重用官方識別及附件校驗不符。檔案先完整驗證，再進入獨立匯入工作階段；不把來源完整性文字當成本次官方認證結果。

Healthbank 資料包、Healthbank 檢驗 JSON/XML 與官方產製的 JSON/XML/PDF 是不同格式。官方原始檔可下載保存；未取得可驗證的格式樣本與語意時，不猜測其欄位來建立通用匯入器。

### 兩份資料包比較

依序選擇前次與本次檔案，完整驗證後在目前頁面比較，不上傳或取代工作區。
以來源內容、語意及父子關聯比較每種內容的出現次數；保留相同內容的重複筆數。
陣列順序、檔案內引用編號、取得時間與本地判讀顏色不作為新增醫療紀錄。
日期範圍、來源集合或判讀版本不同時明示限制；更正可能呈現前後各一筆，
「僅前次保有」不能推定官方刪除。附件以位元組 SHA-256 及來源關聯核對。
畫面每頁最多 50 組差異，完整差異另可下載；循環或無法可靠辨識的關聯不得標為已確認相同。

### PDF／列印專用文件

列印按鈕與 Ctrl／Cmd＋P 開啟專用報表。瀏覽器選單的原生列印同樣在列印前產生專用文件；
若已開啟分享範圍對話框，就使用該份已準備文件，不回退成全部範圍或可見畫面。
預設從全部實際已取得檢驗與醫療資料建立新文件，
不受目前卡片頁碼、捲動位置、年度或搜尋條件影響。逐筆表保留原始值、原文日期、單位、
原院旗標及參考；日期對照表每組最多四個項目，同日所有觀測分別保留。
重複的條件式判讀說明用編號集中列出，不刪除或合併結果。

可另選分享項目、日期與類別；此時僅帶出選中內容及其筆數，不帶未分享類別的全域計數／醫療警告。
來源文字均跳脫，文件不執行腳本、不載入外部資源、不攜帶當次官方識別。
由瀏覽器列印視窗另存 PDF；另有完整 HTML 下載供再次開啟列印。
附件僅列索引，原始 PDF／影像／DICOM 需另存，不宣稱已嵌入這份表格。
PDF 與印表機實際輸出格式受瀏覽器支援影響；合成 Chromium 證據與實體 Safari／印表機驗收分開記錄。

## 7. 保存與驗收

SQLite／MySQL 仍只保存白名單設定與 HMAC 假名化識別。工作區資料、文件與登入憑證不持久寫入伺服器；下載檔案由使用者管理。來源自身的暫存產製及代理／CDN／作業系統保存行為需另行核對。

合成契約、資料模型、實際瀏覽器下載／還原與 CI 可獨立驗證。真實官方登入、個人帳號各來源回傳、歷史完整性、實體 iPhone Safari 及正式 VPS 依[實機驗收清單](acceptance.zh-TW.md)處理。
