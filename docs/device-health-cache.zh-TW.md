# 裝置健康資料快取

本功能經使用者明確同意，將已取得的健康資料保存在目前瀏覽器的 IndexedDB。官方登入仍由官方驗證；伺服器不把快取檢驗、就醫、用藥或附件寫入設定資料庫。此快取與「記住登入欄位」、瀏覽器密碼管理員、自行下載檔案是不同功能。

## 使用流程

1. 完成官方登入後，在「裝置健康資料快取」勾選獨立的保存同意。匿名瀏覽、匯入檔案與合成示範不會自動啟用或寫入個人快取。
2. 目前工作區的檢驗、來源清單、巢狀明細與已保留的小型附件，通過完整資料包驗證後才寫入。面板顯示實際保存時間、檢驗筆數、來源數與位元組大小。
3. 同一網站、同一瀏覽器設定檔日後以相同官方驗證身分登入，可直接開啟該使用者的快取；載入成功時不自動拉取全部歷史。其他使用者的快取不會因切換帳號而自動顯示。
4. 「清除舊資料並重新取得全部來源」先原子清除該使用者舊快取並換代，再清除目前工作區，之後才查詢檢驗、來源清單與遞迴明細。既有保存同意保留；未同意者不因重新取得而自動同意。
5. 重新取得停止、部分失敗或來源不完整時，只保留本輪已取得的結果及明確狀態。舊快取不會自動復原。原始 JPEG、DICOM 及官方匯出檔的產製與大型 ZIP 保存，仍由另行明確操作的完整取得流程處理。
6. 「清除此使用者快取」移除該使用者的快取、保存同意及目前工作區；「清除此裝置所有健康快取」移除本站所有使用者的快取與保存同意。後者亦可在未登入時使用。
7. 登出清除目前工作階段的資料，不撤回已明確同意的裝置保存。需要移除裝置資料時，使用上述清除功能或瀏覽器的清除網站資料。

快取只涵蓋實際已取得、驗證並成功保存的內容。面板的「已保存」不代表官方所有年份與類別均已取得，也不代表任何尚未下載的大型原始檔已存在。

## 隱私與裝置邊界

- 只建議在自己可控的私人裝置啟用。快取使用瀏覽器的網站儲存空間，**應用程式沒有另外加密健康資料**。
- 使用者索引採目前官方驗證後的 HMAC 假名化 `profile_key`。假名化索引不是加密，不是完全匿名，也不是防止裝置管理員或共用瀏覽器設定檔讀取資料的保護。
- 密碼、證號、卡號、官方 Cookie、登入權杖、CSRF 權杖、可重用的官方下載／產製能力不進入快取。保存內容是經白名單驗證的 `healthbank.dataset.v2`。
- 一般頁面操作只會根據本次有效的官方身分開啟相應快取；這項應用程式分流不能取代作業系統帳號隔離與裝置安全。
- 網站來源或伺服器 HMAC 密鑰改變，既有假名化索引可能不再對應目前登入。沒有搜尋其他使用者或猜測身分的回復機制；可在原環境先匯出資料，或使用清除全部功能管理舊內容。
- 瀏覽器私密模式、網站資料清除、儲存配額、系統清理或裝置遺失都可能使快取消失。沒有宣稱瀏覽器永久保存，也沒有把快取當成唯一備份。
- 清除快取不會刪除使用者自行下載的 JSON／ZIP／PDF，也不能代替清除作業系統、瀏覽器設定檔或營運環境的備份。

## 儲存格式、容量與一致性

IndexedDB 名稱為 `healthbank.device-health-cache.v1`，版本為 `1`。`control` 保存全域換代值；`profiles` 保存使用者同意、個別換代值、修訂及摘要；`payloads` 保存經驗證的 JSON `Blob`。未使用 localStorage 作為健康資料快取的替代方案。

| 範圍 | 限制或規則 |
| --- | --- |
| 已同意的使用者 | 每個網站／瀏覽器設定檔最多 8 位 |
| 所有使用者 JSON 內容 | 合計最多 256 MiB；不自動淘汰其他使用者 |
| 單份完整 JSON | 最多 128 MiB，沿用完整資料包限制 |
| 檢驗 JSON | 最多 32 MiB、50,000 筆，沿用匯入與伺服器容量驗證 |
| 保留的附件 | 工作區中合計最多 32 MiB；大型原始檔另存 ZIP |
| 校驗 | 保存與讀取核對精確 UTF-8 位元組的 SHA-256；此校驗檢查內容一致性，不構成官方簽章或醫療真實性證明 |

每次寫入都要提供讀取時的使用者、全域換代值、使用者換代值與修訂。三個 object store 在同一 readwrite transaction 內核對與更新；晚到的舊寫入不能覆蓋新的保存、清除或再次啟用。

「重新取得」更換該使用者的換代值；「清除全部」更換全域換代值並清空同意與內容。非同步 JSON 解碼或雜湊完成後仍需再次核對換代值，避免已清除資料重新進入畫面。

跨分頁通知只傳送操作種類及假名化索引，不傳健康資料。其他分頁收到清除通知或重新取得焦點時會核對實際 IndexedDB 狀態；儲存交易的換代檢查才是最終判定，通知本身不是授權。

如果其他分頁清除了快取，這一頁來自快取的清單、明細與檢驗會移除，且停止自動回寫。**這一頁另行向官方取得的較新檢驗可以保留**，不會用舊快取取代；直接按下清除目前使用者或重新取得的分頁則清除其全部目前工作區。其他分頁保存了較新版本時，舊分頁保留目前畫面並停止覆寫，不會無聲切換資料。

## 官方工作階段的檢驗還原 API

### `POST /api/reports/cache`

此端點只在已完成官方登入、具有有效同源 CSRF 與目前使用階段 Cookie 的情況下，將裝置快取中的檢驗放回**伺服器記憶體**，供既有規則即時重新判讀。它不呼叫健保來源、不寫入 SQL、不把工作階段改成檔案匯入，也不自行證明客戶端歷史描述為真。

請求的白名單欄位：

| 欄位 | 型態與意義 |
| --- | --- |
| `expected_profile_key` | 本次官方驗證的 64 位小寫十六進位假名化索引，必須吻合目前工作階段 |
| `expected_report_revision` | 最近 `/api/session` 回傳的檢驗修訂；清除、更新或其他還原之後舊修訂失效 |
| `saved_at` | 裝置原始保存時間，RFC 3339 |
| `source_fetched_at` | 原來源取得時間，RFC 3339；來源未提供時可為空字串 |
| `source_complete` | 先前快照宣告的完整性，僅作歷史描述 |
| `source_query` | 可選的歷史 `mode`、`start_date`、`end_date`、`reported_count`；不作本次官方查詢證據 |
| `document` | 嚴格 `healthbank.lab.v1` 或 `healthbank.lab.v2` 物件 |

檢驗文件上限 32 MiB，包裝另限 64 KiB。未知欄位、重複 JSON 鍵、大小寫鍵別名、不合法 UTF-8、錯誤型態與超深結構均拒絕。格式、身分、修訂或記憶體容量拒絕不取代先前資料。

成功仍使用一般檢驗回應；目前 `complete` 固定為 `false`，不提供新的 `official_query`，並附：

```json
{
  "kind": "device_cache",
  "saved_at": "2026-10-20T01:02:03Z",
  "restored_at": "2026-10-28T04:05:06Z",
  "source_fetched_at": "2026-10-19T07:08:09Z",
  "source_complete": false
}
```

這個物件位於 `cache_provenance`；可另含歷史 `source_query`，不含身分索引。畫面、完整／選取列印與再次匯出的完整資料包都保留這項歷史來源標示。還原時間不取代原始取得時間。

### `DELETE /api/reports/cache`

請求 `{ expected_profile_key, scope }`，同樣需要有效的官方身分與 CSRF。`scope` 有兩種：

- `all_reports`：重新取得或明確清除的第一步，清除目前伺服器記憶體中的所有檢驗，釋放容量；官方登入與身分仍保留。
- `cache_only`：清除快取來源的檢驗；如果伺服器已另行取得較新的官方檢驗，保留該資料。無論是否有資料被移除，都推進檢驗修訂，撤銷先前排隊中的舊還原。

這個端點不刪除 IndexedDB；裝置清除由前端先完成。官方工作階段、使用者撤銷及檢驗修訂均在既有鎖定與容量邊界內檢查，延遲請求不能將資料安裝到已變更的使用者。

## 原始日期與來源欄位

`healthbank.lab.v2` 在既有原始列上新增可選的 `upload_date`、`source_name`。其中 `upload_date` 是來源原文，輸出時取 API 的 `raw_upload_date`，不以採檢或就醫日期代替。API 另行提供的正規化 `upload_date` 只是顯示／查詢用途；原文即使為空字串也不擅自補值。

舊 `healthbank.lab.v1` 保持嚴格欄位表，不接受新欄位；完整 `healthbank.dataset.v2` 可讀取 v1 或 v2 的檢驗部分。檢驗名稱、原始結果、同日多筆、原院旗標、日期及來源字串不因中英文顯示名稱或快取還原而合併、重寫或改為估計值。

## 驗證界限

合成測試涵蓋真實 IndexedDB 交易、兩個分頁、清除與晚到寫入、雜湊損壞、使用者隔離、實際 App 的保存／下載／還原／取消，以及伺服器的 CSRF、修訂、使用者撤銷與容量回滾。瀏覽器測試的官方登入邊界採明確合成替身，不能列為真實健保帳號登入驗證。

實體 iPhone Safari、裝置私密模式、使用者自己的儲存配額與備份行為仍須在對應環境驗收。這些限制不改變可獨立驗證的嚴格格式、來源標示及伺服器不持久保存健康資料規則。
