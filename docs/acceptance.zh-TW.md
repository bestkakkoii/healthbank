此文件只列出**開發者無法從 CI、合成資料或離線瀏覽器測試代替完成**的真實環境核對，並非另一份功能開發待辦清單。
以下真實環境驗收不應阻擋已完成獨立開發、CI、編譯及封裝驗證的 RC 發布；它們不等於版本仍有可由 Agent 自主完成的開發待辦。

## 已交付

- 以 [GitHub Releases](https://github.com/bestkakkoii/healthbank/releases) 公開、具有 SHA256SUMS 的預覽版為準；使用者應核對目前下載的實際版號與發行說明。
- 以所選發行標籤對應的 [CI／Release Actions](https://github.com/bestkakkoii/healthbank/actions) 是否成功判定測試與建置狀態；舊版 CI 結果不會驗證新版。
- Linux 部署包**沒有多一層版本目錄**，解壓後直接看到 `healthbank`；前端內嵌，不需要在部署機安裝建置依賴。
- 不含使用者的 `data/`、登入憑證、報告或個人健康資料。設定庫僅有假名化索引與有限配置，並非完全匿名；部署者仍需管理主機與第三方服務日誌。

## 使用者真正需要驗收的 4 件事

1. **部署：** 停止現有服務並自行備份**原本**的執行檔和 `data/`（包含 `identity.key`）；下載對應 CPU 的包與 SHA256SUMS，確認雜湊，解壓後只替換 `healthbank` 執行檔，保留原 `data/`。啟動後確認 `./healthbank --version` 與 `/api/health`。不要直接把整包覆蓋原目錄或對外公開 `data/`。
2. **真實官方登入：** 使用者只在自己的網站、官方流程與瀏覽器輸入憑證及圖形驗證碼。確認第一次登入成功後，裝置記憶及瀏覽器密碼管理員能否如預期簡化後續操作。若官方登入失敗，只回報診斷階段／錯誤碼；不要提供密碼、卡號、Cookie、完整封包或驗證碼。
3. **歷史完整性與原始文件：** 在相同帳號與時間範圍，對照官方健康存摺的實際來源、筆數、最早與最晚日期，以及較舊年度、電子處方續領、過敏／接種、篩檢／照護追蹤及生理量測的回傳。核對影像／病理文字、住院文件、官方產製工作及原始附件是否可取得。只要官方沒有可靠總數，就不能聲稱「全部終身紀錄」均已驗證；未回傳不代表沒有就診。慢箋與部分篩檢仍受來源可查範圍限制。各來源詳細限制見 [資料契約](provider-data.md)及[文件契約](provider-documents.md)。
4. **實體設備：** 用預計使用的手機／桌面瀏覽器檢查驗證碼、登入、切換帳號、年齡／性別情境、比較表固定日期與橫向滑動、趨勢、醫療資料工作區搜尋／取消續取、CSV／JSON／XML／SVG 下載、完整資料包匯出還原及列印。確認另行同意的裝置健康快取在同身分重新登入後能開啟，刷新、清除單人／全部及跨分頁清除符合畫面說明；瀏覽器清理網站資料或容量回收後，不能承諾快取仍存在。另核對大型原始附件下載是否受代理或裝置限制。iPhone Safari 與原生密碼管理員行為必須在真實裝置驗收。

## 回報缺陷時

只需要提供：發行版本、作業系統／瀏覽器、操作步驟、預期／實際結果、**去識別後**的錯誤碼或畫面（必要時以合成資料重現）。不得將身分證、健保卡號、密碼、官方 Cookie、權杖或真實醫療報告上傳公開 GitHub Issues。

## 外部條件與保護邊界

- 不可在缺少已授權真實登入的情況下，用合成測試取代官方介面、歷史完整性或身分驗證的正式驗收。
- 不能單憑應用程式不持久保存報告，就保證所有主機、作業系統、反向代理、CDN、WAF 或備份系統「絕對零留存」。部署者必須按實際架構檢查配置。
- MIT 是原始碼授權，不是醫療判讀保證，也不代表任何法院對產品或隱私聲明出具認證。
- 官方匯出格式與 Healthbank 自有 JSON/XML 可攜格式不可混為一談；目前僅已核驗的來源、格式及適用條件可以標示為支援。
