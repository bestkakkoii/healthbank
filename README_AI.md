## Product and boundaries

Healthbank is a self-hosted Traditional Chinese medical-history workspace for older adults with some medical literacy. The official service supplies authorized identity and source data; Healthbank owns acquisition, search, timelines, comparison and portable archives. It does not clone the official site's navigation, administrative services, daily-entry workflows or calculators. The release is a generic executable-first deployment: extract, run the Go executable and configure an HTTPS reverse proxy. No hosting panel is required. The primary deployment target is Debian 13 (trixie) x86_64 using the linux_amd64 release (GOAMD64=v1, CGO_ENABLED=0). React assets and the clinical catalog are embedded. SQLite is default; MySQL is selectable through the same store contract.

Read README.md, docs/clinical-reference.zh-TW.md, docs/comparison-engine.md, docs/privacy.zh-TW.md, docs/nhi_protocol.md and docs/verification.zh-TW.md before changing behavior. Communicate user-facing work in Taiwan Traditional Chinese; technical collaboration may be English.

The additional source contracts are in docs/provider-data.md and docs/provider-documents.md; the application-facing API and archive contract is in docs/data-workspace.zh-TW.md. Public JavaScript establishes observed contracts, not successful live authentication or official API support.

Never persist medical observations, original identity/card numbers, passwords, official tokens/cookies, report HTML, or login histories on the server. Explicit device-local ID/card memory, separately consented health-data caching and optional personal medication/product notes are separate, clearable browser features; they never belong in server settings. User-requested downloads are managed by the user. Only validated configuration documents and pseudonymous verified-subject keys belong in SQL. Keep the stable HMAC key outside SQL. Imported files and demos never authenticate a person or attach to their persisted profile. The IndexedDB health cache contains validated portable v2 data without live capabilities, is keyed only by the verified profile, and is not an encrypted credential vault.

## Source layout and ownership

- cmd/healthbank: CLI, startup, lifecycle, configuration migration.
- internal/config: executable-relative paths, instance lock, random identity key, HMAC subject linkage.
- internal/nhi: fixed-origin official HTTPS protocol, bounded medical category lists/details and session-bound detail references. Manual CAPTCHA only; per-person memory-only cookie jars/JWT; safe error messages and bounded responses.
- internal/lab: canonical mapping, exact rational intervals, clinical grading, HTML/ZIP and versioned Healthbank JSON/XML importers, source catalog.
- internal/store: SQL dialects, schema migrations, optimistic revisions, portable settings snapshots.
- internal/server: typed API, transient session/report memory, same-origin/CSRF checks.
- internal/webui: embedded production assets.
- web/src: accessible React/TypeScript interface. Native SVG charts avoid an extra charting runtime.
- web/public: branded SVG/ICO favicon and Apple touch icon, copied into the embedded frontend by the build script.
- scripts: source-pinned tool bootstrap, typed ESLint runner, strict frontend build/manifest verification, deterministic release archive packaging.
- web/tests: focused synthetic data-model cases for CSV/UTF-8 portable exports, lossless grouping, exact chart points, medication date/day gaps, lipid applicability, rule previews, and large-history chart domains.
- web/dependency-audit.json: every resolved frontend dependency instance, incoming upstream ranges, latest compatible versions, and explicit retained constraints.

## Invariants

1. Link settings only after successful official authentication for that submitted identity. Never accept a browser-supplied pseudonym or treat HTML import as identity proof.
2. Reject unknown fields before persistent writes, including nested portable settings imports. Validate duplicate/case-alias fields, UTF-8 and escaped Unicode before typed decoding; persist exactly the validated canonical document. SQL adapters are not schema-level content validators. Discovery and settings transfers must satisfy the same field, document, snapshot, revision and timestamp bounds as restoration.
3. Refresh/rotate sessions without letting queued or delayed old-generation requests access new-generation data or reissue retired cookies. Bind stateful browser reads and report responses to the exact session token, including same-mode imports; `/api/session` is the explicit reconciliation endpoint. Ambiguous session-changing failures require identity reconciliation without replaying the mutation. A failed reconciliation clears local medical state. Avoid global-lock/session-lock inversion. Server rolling idle expiry is distinct from browser session-cookie restoration.
4. Preserve every result, including same-date duplicates. Source check, visit and upload dates remain separate. Preserve `raw_check_date`/`raw_visit_date`/`raw_upload_date` alongside normalized dates, and retain the separate source code and `source_name`; portable exports retain the source spelling, including explicit empty dates. ROC conversion must not substitute another date.
   Official empty application dates mean all-history (the disclosed 1912-01-01 query floor through Asia/Taipei today); explicit search dates are immutable. The `calendar_events` source includes future scheduled entries, so its empty dates explicitly use the application's accepted 1912-01-01..2200-12-31 bounds. Neither range proves upstream retention. `page_load` defaults must never overwrite explicit dates. Default counts apply as a total only to an identical interval, or as a minimum to a containing interval. Search returns the full array; the SPA's 50-row pagination is local. A same-period count proves consistency only when it equals the actual returned length; preserve contradictory counts and all returned records with an explicit warning. No count implies no independent total verification, not permission to fabricate one.
5. Match names, codes and units together. Never conflate urine/blood Albumin, PH/pH, RBC/WBC, or spot concentration with ratios.
6. Reference flags and official flags survive personal overrides. Reference conformity is not a diagnosis or validated danger score.
7. Compare exact rational decimals; do not round first. Inequalities/ranges stay intervals and never become fabricated chart points.
8. A custom green interval cannot erase independently applicable low-glucose, high-TG or explicitly enabled named-laboratory alert floors. Preserve exact endpoints, units, guaranteed alerts and uncertain categories separately; conditional institutional rules remain inactive without their required context.
9. A missing eGFR unit cannot be silently confirmed by a personal threshold. Source profile demographics/methods are not inferred.
10. Expose all built-in measurement configurations before import, without populating observed items or creating results. Metadata remains excluded; unknown dynamic entries require an observation. Shared ACR and urine-protein settings never collapse source channels. Named reference profiles are previews unless explicitly enabled for fallback. Reset removes overrides and cannot resurrect a preserved conflicting legacy override; retain unrelated appearance/favorites.
11. No external scripts/fonts/analytics, report localStorage, service-worker report cache, uploaded script execution, or multipart disk spooling. The explicitly opted-in IndexedDB cache is the bounded exception for device-local medical persistence; ordinary HTTP API responses remain no-store. Clearing or refreshing must invalidate old asynchronous reads/writes and cross-tab cache leases before fetching again.
12. All human-facing output retains bestkakkoii llc. copyright. Synthetic demonstrations must be conspicuously labelled.
13. Comparison rows are inspection dates and columns are item identities. Annual mode groups dates without aggregating values; preserve every same-date observation within its own item cell. Print column batches must use the same lossless matrix. The user's current requirement freezes the date column on mobile and desktop, including narrow portrait and short landscape; it supersedes the earlier nonsticky mobile design. Scroll padding, final-column visibility, focus and page-arrow steps must reflect the frozen date width.
14. Browser font preferences and in-app reading sizes up to 200% must retain usable controls and readable content. Keep overflow local to two-dimensional tables/charts, protect focus highlights, and do not equate desktop viewport checks with real iOS Dynamic Type or safe-area verification.
15. Prescribing, confirmed dispensing, prescribed duration and actual medication use are different facts. Preserve source categories, classifications and dates; never infer daily dose or adherence from quantity/days. Unknown duration breaks comparisons. Preserve duplicate source events and expose every event through pagination.
16. Lipid formula eligibility uses exact source decimals, matching item names/codes/units and explicit same-collection confirmation. TG above 800 mg/dL and known/suspected Type III exclude Sampson estimates; the optional result never overwrites institutional LDL. The original study and limitations are recorded in the clinical-reference document.
17. Acquisition ranges, unsubmitted date drafts and display filters are separate state. Maximum-range acquisition uses empty application dates; source-only routes retain their actual window. Acquire every selected list before its details, including nested references. Preserve successful results on transient failure; cancellation, retries and explicit capacity limits must never manufacture completeness.
18. Source timelines keep duplicate rows, original date meanings and explicit parent/detail relationships. Matching date/institution is not evidence that two records are one encounter or one specimen. Institutional entries, source self-entry, prescription, confirmed dispensing and actual use remain distinct.
19. Original attachments use fixed routes and opaque session/category references. Large originals stream within 500 MiB/five-minute bounds; buffered PDFs/JPEG groups remain bounded to 32 MiB. Never proxy a browser-supplied upstream URL, execute source markup, or spool medical files. Temporary official file generation is an explicit CSRF-protected action, never a side effect of automatic list/detail acquisition.
20. healthbank.dataset.v2 includes all fetched source lists/details, coverage, explicit source semantics, producer/catalog/evidence revisions and retained attachments, independent of display filters. Strict v1 imports remain supported with unknown producer provenance; never retrofit v2 fields into v1. Export rewrites live handles into local archive references and omits official actions/credentials. Import validates UTF-8, schema, duplicates, bounded structure and attachment SHA-256 before changing the session; it never proves ownership or writes a medical dataset to SQL. An archive lacking a detail or attachment must continue to disclose that absence. Snapshot comparisons use source-aware multisets, retain duplicate multiplicity and do not infer amendments or deletions.

21. Standalone source exports use the same safe handle projection as full datasets. Late device-note file reads cannot restore cleared content or consent. Render diagnostics use fixed safe codes, never raw React error/component stacks or medical props. Exact personal interval validation belongs to the server's rational arithmetic; browser floating-point approximations must not reject valid narrow intervals.

22. Printing uses a separate escaped document generated from actual data, not the current viewport, paginated cards or DOM screenshot. Default scope is all acquired records; explicit sharing scopes must not leak excluded source counts or global clinical warnings. Preserve raw results, dates, flags and duplicates, index repeated interpretation text without merging measurements, and retain full text across pages. Browser PDF output requires no production Chromium service.
23. Unit normalization is a finite case-sensitive map; m/M and other SI prefixes cannot be case-folded. Legacy ambiguous dynamic keys remain isolated and disabled without altering unrelated shared configurations. Clinical evidence-registry.json records source loci, eligibility, independent vectors and exact implementation hashes; legitimate implementation edits update those hashes and the accompanying tests deliberately.
24. Resource limits are logical admission accounting, not an RSS promise. Preserve old reports/handles on rejection; callbacks acquire only the budget mutex and releases cannot be refused. Per-session queues honor cancellation. Readiness is direct-loopback only and exposes no identity/key check or medical content; liveness is separate. Schema-2 key checks never certify an unknown legacy key pairing or silently block ordinary legacy upgrades.
25. Optional date batches use explicit bounded nonoverlapping periods and only date-search sources plus selected labs. Preserve each current batch's successes, reject stale previous-period labs, and require export plus a separate saved-file acknowledgment before explicit advancement. Keep previous summaries only, preserve unselected workspace content, and do not persist checkpoints. Source-only windows, attachments and missing totals remain explicit; completed requests do not prove complete lifetime history.
26. Full acquisition is an explicit user workflow: current lists, recursive details, optional one-shot source preparation, bounded correlated refresh and original downloads. Never replay an ambiguous preparation. Uncorrelated original-file jobs stay uncorrelated; timestamps, filenames and counts cannot supply a missing official job ID. File-only retry preserves exact dataset bytes and archive IDs and skips saved successes. ZIP bytes stream without disk spooling; dataset/reference/receipt retention participates in the existing budget. Package completion, per-file usability, user save acknowledgement and source completeness are separate states.
27. Keep the entire current public source graph in review scope: every entry script and lazy chunk, including newly added modules. `docs/provider-source-inventory.json` contains factual hashes, route/operation classifications and implementation/exclusion mapping; `provider-contracts.json` pins field/date/unit declarations. Source field equivalence does not prove equal unseen response rows: retain separately returned source chart/snapshot channels when the API can return them independently. Public code classification is not proof of undocumented routes or real-account history.
28. Count equality alone does not establish laboratory row retention. When the requested interval contains the initial source interval, require every initial row with its original field values and duplicate multiplicity to remain in the returned full-search array. A mismatch is an explicit incomplete response, never a reason to invent, deduplicate or merge observations across incompatible snapshots.
29. Device health-cache consent is per verified user and independent of remembered login fields. A later official login may restore the same profile's cached data without a full upstream fetch; imports/demos cannot opt in or enumerate profiles. Server restoration is memory-only, guarded by exact identity, session and report revision, and always marked as cache provenance with current completeness false. Preserve historical source metadata separately. Explicit refresh clears old data first; clear-one/all revokes corresponding consent, while refresh preserves existing consent. Do not promise physical erasure of browser/OS backups or downloaded files.
30. Chinese/English terminology is display metadata, not measurement identity. Preserve original names and distinguish literal official payment terminology from editorial names grounded in primary sources. A billing code can cover several analytes; uncertain specimen, method or parameter meanings stay uncertain. New portable laboratory fields belong to `healthbank.lab.v2`; strict v1 imports retain their original schema.

## Build and verification

Use scripts/bootstrap-upstream.sh, dependencies.lock.json and web/package-lock.json. The current source snapshot is recorded in Asia/Taipei time; direct application sources and all linked Linux Go modules were checked against official upstream HEAD. Other tools use verified official sources/releases/prereleases. Preserve immutable commits and hashes. Do not silently substitute older release packages or claim every graph-only/transitive package is newest when upstream API/peer constraints retain another version. DEPENDENCIES.md and web/dependency-audit.json contain the exact exceptions.

Bootstrap installs the Node.js, npm and Go/compiler revisions recorded in dependencies.lock.json. Add .tools/bin and .tools/go/bin to PATH after it returns; unset an inherited GOROOT and use GOTOOLCHAIN=local, GOENV=off and GOWORK=off for reproducible verification. Production compilation uses the pinned native TypeScript compiler; typescript-eslint separately uses its supported JavaScript compiler API. Do not suppress an unsupported-version warning or bypass peer requirements to merge those two roles. Compiler caches are keyed by source and Go revisions and validated against actual embedded Go metadata.

Run npm --prefix web run lint (typed strictTypeChecked rules, current React Hooks recommendations and --max-warnings 0), the strict TypeScript production build, and npm --prefix web test. The model tests cover substantive data invariants rather than CSS implementation. Fix defects behind diagnostics; do not lower severities, hide warnings or introduce broad assertions solely to obtain a clean report. Review any intentional lint-policy options in context.

Run gofmt, the full Go suite, the race suite, go vet, go mod verify, pinned `staticcheck -checks=all ./cmd/... ./internal/...`, and Linux amd64/arm64 cross-compilation. Staticcheck covers all first-party Go packages; npm dependencies may contain unrelated Go example packages and are not application source. Do not disable individual checks to silence diagnostics. The grading/parser, settings isolation/migration and official-protocol fixture tests protect substantive invariants. MySQL integration is opt-in locally via HEALTHBANK_TEST_MYSQL_DSN to an isolated empty synthetic database; CI provisions the digest-pinned MySQL service declared in its workflows. Concrete tested revisions and migration evidence belong in docs/verification.zh-TW.md. An absent DSN means a skip, not a pass. Do not use a production database for integration tests.

A production frontend build clears its output directory and writes frontend-build.json with input hashes, artifact hashes and the Node version. Run node scripts/build-web.mjs --verify before Go embedding or packaging; scripts/release.sh also requires it. A changed input, modified output or extra artifact requires a rebuild. This manifest does not independently establish TSC/esbuild executable provenance: retain the pinned-tool metadata checks, especially when using explicit TSC/ESBUILD overrides. Do not edit the manifest to conceal stale artifacts.

npm audit and govulncheck use live advisory databases and may legitimately fail a later run. The current govulncheck cannot semantically classify the development Go standard-library version; do not claim that a zero-finding result clears the development standard library or substitute a fake GOVERSION.

Keep credentialless CAPTCHA retrieval evidence, earlier connection failures, and the exact tested executable identity in docs/verification.zh-TW.md. Image retrieval does not establish authenticated login, historical completeness, global official availability, or successful display on a user’s deployment.

Recheck visual changes in a browser and disclose missing real-device verification. The authenticated live NHI flow remains unverified unless a user actually completes an authorized login on a reachable deployment. An upstream HTTP503 is an availability result, not evidence of global outage or bot detection. Do not request credentials in chat or solve CAPTCHA automatically. The synthetic MySQL test does not certify the user's database, deployment environment or physical iOS/Safari environment.

The checked-in browser gate uses scripts/browser-acceptance.mjs and checksum-pinned test-only Chromium/CJK assets. Run it against the actual compiled executable; the release gate tests the extracted amd64 package. Retain synthetic summaries/PNG/PDF evidence only, excluding runtime settings databases, keys and cookies. PDF text checks must cover every record beyond viewport/page boundaries and visual review must inspect pagination, Chinese glyphs and selected-scope metadata. Offline provider registry tests run in CI; an explicit --online maintenance check follows the current entry bundle and chunk map instead of accepting an old URL merely because it still exists.

The `diagnose-nhi` command uses the production connector without loading configuration, opening SQL, or acquiring the serving instance lock. It must not accept an upstream override or credentials, retry authentication, print image/challenge contents, or downgrade TLS. Diagnostic phases identify observed client-side progress, not the responsible remote component; a negotiated TLS peer may be a configured proxy.

## Release

The source archive is explicitly allowlisted by scripts/release.py, including RELEASE_CANDIDATE. Keep raw reports, upload directories, .tools, databases, identity.key, environment files and logs outside it. Binary archive staging rejects private/temporary paths and extracts at the root without a version directory. Build and verify the compiled frontend before Go embedding. Official release packaging requires the actual Git root, a clean tracked/index state and every allowlisted input tracked, including otherwise ignored additions. Symlink directories and nonregular inputs are rejected. Any explicit COMMIT must resolve to HEAD; SOURCE_DATE_EPOCH must match its timestamp. Produce exactly the selected version's Linux amd64/arm64 and source archives with SHA256SUMS, notices/licenses and deployment/clinical/verification documents. Before publication, resolve any existing lightweight or annotated version tag to the exact build commit; API lookup failures are not evidence of absence. Ordinary source-archive consumers can build the application without official release packaging. Run python3 -W error scripts/test_release.py. Local packaging does not authorize publication to GitHub or a user's server; preserve explicit session authorization when provided.
