## 寶塔部署：上傳、選擇執行檔、綁定網域、啟動

**主要部署目標：Debian 13（trixie）x64／x86_64。請選 `linux_amd64`，採 `GOAMD64=v1` 與純 Go 靜態編譯。**

1. 一般 Intel／AMD 64 位元主機下載 `healthbank_1.0.2_linux_amd64.tar.gz`；ARM64 主機下載 `linux_arm64`。
2. 在寶塔檔案管理中上傳並解壓縮，例如放在 `/www/wwwroot/healthbank/`。解壓後可把套件內層目錄當成專案目錄。
3. 在寶塔 **Go 專案**新增專案，選擇解壓出的 **`healthbank` 執行檔**。無需啟動參數，預設服務位址為 **`127.0.0.1:8787`**；面板需要填埠號時填 **8787**。
4. 綁定已指向這台主機的網域，啟動專案。由寶塔的網站／Go 專案反向代理映射至該埠號，使用該網域瀏覽。正式登入請使用寶塔管理的 **HTTPS**。

**不必安裝 Go、Node.js、Python、Chromium 或 MySQL，也不必在伺服器編譯前端。** 前端與預設資料表已內嵌在執行檔。第一次啟動會在執行檔旁建立 `data/`。

如果面板沒有保留執行權限，在檔案權限中把 `healthbank` 設為可執行（755）。不同寶塔版本的欄位名稱可能略異；完整欄位對照與可選 Nginx 設定見 [部署說明](docs/deployment.zh-TW.md)。`deploy/nginx.healthbank.conf` 只供此 APP 的網站使用；已有面板映射時不需重複加入 `location /`。

## 使用方式

開啟網頁後，可選擇「連接健康存摺」、「匯入已下載網頁」或「先看看功能示範」。

官方登入使用本人證號、健保卡號、註冊密碼與**手動輸入的圖形驗證碼**。開啟登入視窗即自動向官方取得驗證碼圖片，不需先輸入登入資料；圖片中的文字仍由本人填寫。健保卡號可直接輸入 8 碼，前方自動補 `0000`，或輸入完整 12 碼；前導零不會遺失。預設在這部裝置記住證號與卡號，可隨時取消並清除。密碼只提供瀏覽器的密碼管理器介面；應用不把密碼寫入資料庫或瀏覽器儲存區。密碼管理器依網域識別，首次使用自架網域時可能需要手動選擇或儲存。

每位家人分別使用自己的官方登入資料。登入成功後，同一人在手機、電腦取得相同的個人設定；不需要另建 APP 帳號。檢驗結果每次向官方取得，關閉／登出或連線到期後需重新取得。

### 四個主要畫面

| 畫面 | 功能 |
| --- | --- |
| 檢驗總覽 | 最近檢查、涵蓋年度、優先檢視、關注項目、來源與完整性提醒 |
| 年度比較 | 每列為檢查日期、每欄為檢驗項目；可按年份分組或連續列出日期；搜尋、類別／年度篩選、關注／異常篩選；同日多筆結果分開保留 |
| 數值趨勢 | 手機預設呈現完整時間範圍、實際日期間隔、原院或個人參考陰影、對數刻度、完整明細、SVG 圖表下載 |
| 個人設定 | Light／Dark／跟隨系統、文字大小、關注項目、已出現檢驗項目的個人上下限與最多16個不重疊分級區間 |

可匯出 UTF-8 CSV，也可使用「列印／PDF」開啟瀏覽器列印。報表、圖表與匯出內容附有 **bestkakkoii llc.** 版權。介面可在筆電及現代 iOS Safari 使用；實體 iPhone／Safari 的最後驗收仍需在部署後完成。

比較表固定左側日期欄，檢驗項目橫向展開；手機日期欄縮至約三分之一可視寬度，以年份／月日分行，不隨閱讀字級成倍加寬。上方提供可見的左右捲動滑桿與箭頭按鈕，桌面閱讀長表格時保留操作列，不必先捲到最底部。列高隨實際內容調整，短內容緊湊呈現，長內容自然換行。同日同項目有多筆結果時，會在同一格中分筆呈現；該日期列會隨內容較多的儲存格增高。列印時每段最多 4 個項目欄，重複日期與項目標題，便於逐頁閱讀。

「個人設定 → 閱讀字級」提供 100%、110%、120%、150% 及 200% 五種字級。文字放大時，操作列與表單會換行；比較表保留獨立的橫向捲動區。趨勢圖依容器寬度與字級重算座標，減少或換行日期刻度，保留所有可繪製資料點，預設不需左右捲動即可看完整時間範圍。基礎字級採相對尺寸，配合瀏覽器字級偏好與 Safari 網頁縮放；這不等同於已驗證所有 iOS 系統 Dynamic Type 設定。

## 資料與醫學判讀原則

內建 **72 個來源項目定義：70 個測量項目、2 個流程／項目附註**，另有未知項目的動態對應。項目身分結合醫令代碼、原始名稱與單位；血液白蛋白與尿白蛋白、尿液 PH 與靜脈血液 pH 不會被合併。ACR 定量與半定量共用分類設定，但保留不同結果列。

原院每筆報告的參考值、異常標記、檢查日期、就醫日期、單位與醫事機構都保留。個人設定改變的是顯示基準，不會改寫原始報告。

| 顏色 | 本應用含義 |
| --- | --- |
| L1 綠 | 基準內 |
| L2 黃 | 邊界／留意 |
| L3 橘 | 異常 |
| L4 紅 | 顯著異常／需評估 |
| L5 紫 | 最高警示 |
| 灰 | 缺值、資料不足、跨越分類界限或不適用 |

五種顏色是本應用的顯示方式，**不是通用的「2026亞洲人五級危險標準」**。只有具有適用來源的項目使用相應分類；一般參考區間只判定基準內／偏高／偏低，不把偏離百分比硬分五級。原院未給參考值時，不會默默套用範例中的性別、年齡或儀器範圍。

`≥300`、`>150`、`0–5`、`4+`、`Negative` 與缺值各自保留型態。非精確數值不畫成精確資料點；可確定的低血糖／高三酸甘油脂警示下限不因個人設定而消失。單位未確認的 eGFR 不直接套用分類。完整來源、版本、界限與使用限制見 [醫學參考規則](docs/clinical-reference.zh-TW.md)。

歷史資料會保留當次原院參考值；指南分類採這個程式版本所列的來源版本，不聲稱還原每一年當時的指南。這是整理及輔助閱讀工具，不會自行診斷疾病或建議藥物劑量。

## 匯入及官方連線的驗證範圍

HTML／ZIP 匯入在記憶體解析十欄明細表，不執行網頁腳本，不把重複的三欄摘要再算一次，也不擷取病人頁首。限制：原檔12 MiB、解壓 HTML總量6 MiB、ZIP最多4096項目。

**另存網頁可能只有當時那一頁。** 系統會明示無法證實完整歷史，不會把缺少的分頁當成沒有檢查。匯入資料沒有官方身分驗證，因此使用獨立的暫存設定，不連結到已登入者的持久設定。

官方連接器已依使用者提供的官方公開程式碼實作 CAPTCHA、登入、完整查詢、更新權杖及登出，並通過本地合成協定測試。此環境對官方登入頁及 CAPTCHA 的公開 GET 曾收到 HTTP503；**沒有使用真實帳號完成線上登入驗收**。這是本次驗證限制，不能解讀為官網對所有人停機。部署主機仍需能正常連到健保署；官網介面變更時需更新連接器。詳細協定與驗證邊界見 [NHI protocol](docs/nhi_protocol.md)。

## 保存內容與備份

| 位置 | 保存內容 |
| --- | --- |
| SQLite／MySQL | HMAC產生的帳號識別鍵、已遇到的項目定義、個人基準、關注項目、外觀與設定版本 |
| `data/identity.key` | 自動產生的穩定識別金鑰；與資料庫分開保存 |
| 裝置瀏覽器 | 使用者同意記住的證號／卡號、外觀偏好；密碼由瀏覽器自行管理 |
| 伺服器及分頁記憶體 | 本次官方 Cookie／權杖與檢驗結果；不存入資料庫、檔案或應用日誌 |

應用使用階段約30分鐘；閒置連線會清理。瀏覽器可能清除長期儲存區，私密模式也可能不保存資料，無法保證裝置永遠記住登入欄位。

更新時保留整個 `data/`，尤其 **資料庫與原本的 `identity.key` 要一起備份**。遺失金鑰會使既有帳號設定無法對應。伺服器端識別屬於假名化連結，不能宣稱完全匿名。最低限度的隔離、HTTPS、同源寫入及不記錄敏感請求，已整合進程式。

預設 SQLite；以 `HEALTHBANK_DB_DRIVER=mysql` 與 `HEALTHBANK_MYSQL_DSN` 可選 MySQL。提供獨立於資料庫引擎的設定匯出／匯入，匯入必須是空目的庫且保留原金鑰。**不是把 .sqlite 檔案直接交給 MySQL。** [遷移操作](docs/deployment.zh-TW.md)包含步驟；本次沒有可用的實際 MySQL 伺服器，MySQL 整合測試明確標示為未執行。

## 原始碼建置

一般部署直接使用 Linux Release。以下僅供開發者，需 Linux x86_64建置主機、Node.js24.22.1或相容版本、npm、curl、tar、Python3，以及下載官方來源的網路。建置工具及直接依賴固定至已核對的上游提交，詳見 [DEPENDENCIES.md](DEPENDENCIES.md)。

```bash
bash scripts/bootstrap-upstream.sh
npm --prefix web ci
npm --prefix web run build
.tools/go/bin/go test ./...
.tools/go/bin/go vet ./...
GO="$PWD/.tools/go/bin/go" bash scripts/release.sh v1.0.2
```

輸出為 `dist/releases/` 內兩種 Linux架構套件、原始碼套件與 `SHA256SUMS`。二進位採 `CGO_ENABLED=0`；伺服器不需編譯工具或外部動態 SQLite 函式庫。原始碼包不含真實報告、登入資料、資料庫、金鑰或開發快取。

專案分層：`cmd/healthbank` 啟動／維護指令；`internal/nhi` 官方連線；`internal/lab` 解析、分類與來源目錄；`internal/store` SQL設定儲存；`internal/server` HTTP及使用階段；`web/src` React介面；`internal/webui` 前端嵌入。AI與維護者請先閱讀 [README_AI.md](README_AI.md)。

專案提供 CI 與 Release 工作流程，執行狀態以 [GitHub Actions 紀錄](https://github.com/bestkakkoii/healthbank/actions)為準。維護者推送版本標籤時，工作流程會準備草稿 Release；公開發行檔以 [GitHub Releases](https://github.com/bestkakkoii/healthbank/releases)列出的版本為準。本機建置驗證與 GitHub 工作流程執行結果分開記錄。
